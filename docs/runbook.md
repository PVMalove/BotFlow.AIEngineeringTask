# Запуск и проверки BotFlow

## Подготовка демонстрации

Нужны Docker Compose 2.24+, Python 3.12, uv и Node.js 24.
Команды выполняются из корня репозитория.

```bash
cp .env.example .env
make init
```

В `.env` задайте числовой `INITIAL_ADMIN_TELEGRAM_ID` первого администратора.
Токен от BotFather запишите в `.secrets/telegram_bot_token`.
`make init` создаёт остальные локальные credentials и не перезаписывает существующие.
Файлы `.env`, `.secrets/` и содержимое приватных голосовых записей не коммитятся.

```bash
make whisper-prepare
make demo
```

Подготовка Whisper скачивает и проверяет веса модели в постоянном томе
`botflow_whisper_models`. По умолчанию используется `turbo`, веса занимают
около 1.5 GiB. Модель можно выбрать через `WHISPER_MODEL` в `.env`.

`make demo` выполняет preflight, собирает образы, применяет миграции трёх БД,
создаёт первоначального администратора и приватный bucket MinIO, запускает
API, SPA, бота и workers. Повторный запуск сохраняет данные и не восстанавливает
отозванные права администратора.

Панель открывается на [localhost:8080](http://localhost:8080). Отправьте боту
`/login` в личном чате и вставьте код на странице входа. Код одноразовый,
действует 5 минут. Новому участнику нужен одобренный администратором допуск.

```bash
make down
```

Команда останавливает стенд, включая бота и workers, с сохранением томов.
Следующий `make demo` использует сохранённые данные.

## Разработка и автоматические проверки

```bash
make deps
make check
make test
make build
npm --prefix frontend exec -- playwright install chromium
make e2e
```

`make deps` устанавливает зависимости из lockfiles. Проверки самостоятельно
их не устанавливают. `make check` запускает линтеры, проверку типов и формата
без автоисправлений. `make test` проверяет backend, frontend и служебные скрипты.

`make e2e` создаёт отдельный Compose-проект с уникальными именами, своими
секретами и томами. Проверяются реальные PostgreSQL, RabbitMQ, Redis и MinIO,
вход через nginx, доступ, задачи, конфликты версий, realtime, RU/HY и узкий экран.
Внешние Telegram и STT заменены тестовыми адаптерами.
Пустой или частично пропущенный браузерный прогон считается неуспехом.
После проверки удаляются только ресурсы этого тестового проекта.

Отдельный инфраструктурный smoke запускается через `make smoke`.
При проблемах DNS во время Docker-сборки в локальном окружении:

```bash
BOTFLOW_BUILD_NETWORK=host make smoke
```

Для разработки только интерфейса: `npm --prefix frontend run dev`.
Проверка интерфейса с тестовыми HTTP-ответами: `npm --prefix frontend run test:ui`.
Полноценный вход с настоящей сессией требует общего origin через Compose ingress.

## Диагностика фонового задания

```bash
make job-status JOB=<uuid>
make job-replay JOB=<uuid>
```

Первая команда показывает статус, попытки и безопасный код ошибки.
Вторая повторяет failed-задание с прежней идентичностью и заново проверяет
лимиты приёма. Создание Task защищено от дублей по источнику и inbox.

Для проверки локального распознавания доступны `make whisper-verify`,
`make whisper-corpus-check` и `make whisper-bench`. Корпус и результаты
хранятся локально в `.local/whisper/`.

Полный список команд: `make help`.
Архитектурные детали: [архитектура](architecture.md),
[локальная инфраструктура](local-infrastructure.md).
