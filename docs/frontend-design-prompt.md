# Промпт для доработки UI BotFlow

Отрефактори существующий UI BotFlow. Сохрани React, TypeScript, Vite,
Material UI, React Query, авторизацию, существующие API и бизнес-правила.
Все подписи, ошибки, инструкции drag-and-drop и валидацию поддержи на RU/HY.
Не переводи пользовательский текст и имена. Используй локальные шрифты.

## Стиль и компоновка

Тёплая палитра: фон `#F6F4F0`, белые карточки `#FFFFFF`, горчичный акцент
`#D9A74A`, рамки `#EAE6DF`, основной текст `#1F1E1C`. Контейнер по центру,
`max-width: 1200px`. Тонкие рамки, умеренные скругления, минимум теней.

## Шапка и навигация

Белая шапка: слева логотип `B.` и BotFlow, справа «Русский / Հայերեն».
Без Live-бейджа и индикатора синхронизации. Под ней одна компактная строка:
слева «Командная доска» и, для admin, «Управление доступом»; справа Telegram-ник
текущего пользователя, при его отсутствии отображаемое имя, и «Выйти».
Активная вкладка полужирная, с горчичным подчёркиванием. На мобильном экране
разреши перенос строки без горизонтального переполнения.

## Название доски

Над колонками показывай название конкретной доски, например «Запуск BotFlow»,
а не фиксированное «Командная доска». Рядом маленькая кнопка-карандаш.
Нажатие открывает поле: Enter сохраняет, Escape отменяет. Пустое или состоящее
из пробелов имя запрещено. При ошибке введённый текст остаётся в поле,
рядом сообщение. На время запроса заблокируй повторную отправку. Проверяй
право редактирования по серверному контракту. Удали подзаголовок
«Все задачи команды в одном месте».

## Доска и карточки

Desktop: три равные колонки, промежуток 24px: «Ожидает», «В работе»,
«Завершено», с актуальным количеством в скобках. Mobile: колонки вертикальны.
Карточка компактная, длинный текст переносится. Состав:

- источник и время мелким серым текстом: «🎙 Голос • 22 окт. 2026 г., 22:57»
  или «💬 Текст • …»;
- текст задачи: 15px, полужирный, `#1F1E1C`;
- автор: «Malove (@maloveee)», меньшим серым текстом.

Без сегментированных переключателей и дублирующих статусных бейджей.
Сохрани пагинацию каждой колонки, обновление и сообщения об ошибках чтения.

## Окно задачи и сохранение

Клик или Enter на карточке открывает доступное модальное окно с полным
текстом, источником, датой, автором, обычным dropdown «Статус» и кнопками
«Отмена»/«Сохранить». Автор меняет свои задачи, admin — любые; чужую задачу
обычный пользователь может читать без действий изменения.

Только «Сохранить» отправляет существующий `PATCH /api/v1/tasks/{id}` с
`status` и `expected_version`. Во время запроса блокируй повторную отправку.
Успех переносит карточку, обновляет счётчики и закрывает окно. Ошибка
оставляет окно открытым и показывает локализованное сообщение. При 409 или
потерянном ответе сначала перечитай `GET /api/v1/tasks/{id}` и загруженные
страницы доски, покажи актуальный статус и предложи решить заново.
Автоматически не повторяй PATCH. Если чтение не удалось, новое сохранение
запрещено до успешного ручного повторения чтения. Актуальный no-op допускается
API и не увеличивает версию. После серверного отказа соблюдай текущие права.

## Перетаскивание

Используй `@dnd-kit/core`. Ручка на карточке начинает перенос мышью/touch,
покажи место вставки в серверном порядке `created_at + ID` и выдели колонку.
Перенос в другую колонку вызывает тот же PATCH. Перенос внутри текущей
колонки или отмена не отправляют запрос. Свободной сортировки внутри колонки
нет. При оптимистичном переносе ошибка возвращает карточку на прежнее место;
при переносе после подтверждения оставь карточку на месте до успешного ответа.
Ошибки видны в уведомлении; 403/409 и неопределённый исход вызывают
перечитывание карточки и доски без повторного PATCH. Используй версию начала
переноса; поздний ответ не затирает уже известную более свежую версию.
Завершение drag не открывает окно. Прокрутка карточки не начинает перенос;
`touch-action: none` относится только к ручке. Предусмотри отмену и пустую
колонку. Escape отменяет активный перенос мышью/touch. С клавиатуры карточка
открывается через Enter; статус меняется обычным select в окне и сохраняется
кнопкой. Перенос стрелками исключён из объёма #18 по решению пользователя.

## Управление доступом

Фильтры: «Заявки (0)», «Отклонённые (0)», «Участники (2)», активный — с
горчичным подчёркиванием. Используй реальные счётчики API с учётом пагинации.
Строки участников горизонтальные, padding `16px 24px`: слева аватар 44×44px,
имя/ник и Telegram ID мелким серым текстом. Справа роль, зелёный «Допущен»,
кнопка с обводкой «Заблокировать». Между действиями 12px. На узком экране
строка переносится. Сохрани заявки, отклонения, разблокировку, запрет
самоблокировки, права admin, ошибки и пагинацию.

## Граница текущего API и последующая работа

Это целевой дизайн. В срезе #12 доступны PATCH/GET задачи и отображаемое имя
сессии. Название доски и право его менять, тип источника, Telegram username,
URL аватара и общие totals отсутствуют. Не подставляй фиктивные значения и
не сохраняй общее название только в localStorage. Пока название — «BotFlow»,
источник — «Telegram», автор — существующий `author_name`, аватар — инициалы.
Счётчики отражают загруженные записи: `50+`/`20+` при наличии или возможном
наличии следующей страницы; «…» при загрузке, «?» при ошибке.

После готовности backend:

1. Получи модель единственной доски с названием, версией и правом изменения;
   подключи карандаш и сохранение с обработкой Enter/Escape, пустого имени,
   ошибок и конфликта версии. Права определяются сервером.
2. Прими nullable `telegram_username` у сессии/участников и `author_username`
   у задачи. Ник показывай с одним `@`; иначе сохраняй fallback имени.
3. Прими nullable `source_type: text | voice` у задачи. Только известные
   значения показывай как «Текст»/«Голос» с соответствующей иконкой.
   Старые записи без источника остаются «Telegram».
4. Подключи nullable URL аватара с fallback на инициалы и безопасным alt.
5. Замени счётчики загруженных записей на серверные totals по статусам задач
   и фильтрам доступа. Обновляй totals после мутаций и refresh; не загружай
   всю историю ради подсчёта и не ломай текущие ответы API.
6. Добавь браузерные проверки названия, прав, серверных отказов, неизвестного
   источника, username fallback и totals при нескольких страницах на RU/HY.
