# Веб-панель BotFlow

## Визуальное направление

Самостоятельный рабочий интерфейс BotFlow: белая шапка, фон `#F6F4F0`,
карточки `#FFFFFF`, горчичный акцент `#D9A74A`, рамки `#EAE6DF`, основной текст
`#1F1E1C`. Контейнер по центру, до 1200px, тонкие рамки, умеренные скругления
и минимум теней. Локальные Montserrat и Noto Sans Armenian; внешнего CDN нет.
Material UI настраивается общей темой. Пользовательский текст не переводится.
Полный актуальный [дизайн-промпт](frontend-design-prompt.md) описывает шапку,
навигацию, карточки, окно задачи, перенос и доступ, а также ожидающие API поля.

## Русский и армянский

Видимый переключатель «Русский / Հայերեն» доступен до входа и после входа,
на широком и узком экране. Локали — ru и hy. Начальный язык — ru; явный выбор
сохраняется в localStorage и восстанавливается после перезагрузки.
Переключение не требует повторного входа и не сбрасывает состояние доски.
Атрибут html lang соответствует выбранной локали.

Переводятся навигация, формы, кнопки, статусы, валидация, пустые состояния,
ошибки, состояния соединения и административные действия. Даты/числа
форматируются Intl для выбранной локали. Машинные статусы API и error codes
остаются стабильными; frontend отображает переводы из локальных словарей.
Простой слой словарей ru/hy достаточен; отдельный сервис переводов не нужен.

Текст задачи, транскрипция и имя автора сохраняются как есть: переключатель
не переводит пользовательские данные. Язык веб-интерфейса не меняет
автоопределение языка Whisper. Двуязычные сообщения самого Telegram-бота
в обязательную первую версию не добавляются этим решением.

## Доска и критерии приёмки

- Три колонки с локализованными Pending / In Progress / Completed,
  явный выбор статуса и Drag & Drop между колонками на @dnd-kit/core.
  Перенос вызывает ту же mutation с версией; без сортировки внутри колонки.
- На узком экране колонки вертикальны; шапка и переключатель языка доступны,
  армянские подписи и длинный текст не ломают карточки/формы.
- Обработаны loading, empty, error, reconnect и конфликт версии.
- Проверка RU → HY → reload → RU охватывает вход, доску и admin-экран;
  текст уже созданной задачи остаётся неизменным.
- Playwright проверяет основной путь на двух языках и узком экране;
  ручной просмотр проверяет глифы и отсутствие чужого брендинга.

Drag & Drop сохраняет owner/admin права и обработку 409/неопределённого ответа
без повторного PATCH. Поддерживаются мышь и touch, drag-ручка,
отмена, пустая колонка и RU/HY инструкции. Обычная прокрутка/кнопки карточки
не запускают случайный перенос; сортировка остаётся created_at + ID.

Это согласованный дизайн-контракт; состояние реализации доски описано ниже.

## Реализованный срез: чтение доски (#10)

Доска читает `/api/v1/tasks` отдельно для каждого статуса, по 50 карточек.
«Показать ещё» передаёт непрозрачный курсор сервера; порядок — убывающие
`created_at` (с точностью PostgreSQL до микросекунд) и UUID. Пересекающиеся
страницы объединяются по ID с предпочтением большей версии задачи.

Обновление по кнопке, возврату фокуса, восстановлению сети и раз в 30 секунд
перечитывает загруженные страницы последовательно от начала с новыми курсорами.
После стабилизации изменений это восстанавливает непрерывную историю; оставшаяся
история доступна через «Показать ещё». Ошибка следующей страницы сохраняет
прочитанные карточки; «Повторить» повторяет только неудавшееся чтение. Ошибки
обновления помечают показанные данные как потенциально устаревшие.

RU/HY локализуют статусы, время и состояния интерфейса, сохраняя текст и имя
автора. На узком экране колонки расположены вертикально. Изменение статуса
и Drag & Drop реализованы в срезе #12 по расширенному запросу. WebSocket-синхронизация остаётся следующим срезом.
`frontend/e2e/board.spec.ts` включён в общий `make e2e`: настоящий REST,
пагинация каждой колонки, новая задача сверху, перемещение между страницами
через тестовую БД, отсутствие дублей/пропусков, RU/HY и узкий экран.

## Реализованный срез: статус и компактный UI (#12)

Карточка открывает модальное окно; выбор dropdown сохраняется по «Сохранить»
через PATCH с наблюдаемой версией. Автор меняет свои задачи, admin — любые.
No-op отправляется с актуальной версией. При успехе задача заменяется во всех
загруженных страницах без дублей, затем доска перечитывается. Ошибки остаются
в окне; 409 и неизвестный результат вызывают GET карточки без повторного PATCH.
Неуспешное согласование блокирует новое сохранение до успешного ручного GET.

Перенос через ручку использует PointerSensor (мышь/touch, порог 8px),
локализованные инструкции и отмену через Escape. Только ручка имеет
`touch-action: none`. Место вставки соответствует серверному порядку;
карточка перемещается после успешного PATCH, поэтому откат не требуется.
Перенос в ту же колонку и отмена не отправляют PATCH, drag не открывает окно.
Обычная кнопка карточки открывает окно с клавиатуры.

Навигация показывает отображаемое имя из сессии вместо Telegram ID. Доступ
оформлен горизонтальными строками с аватаром-инициалом 44px, ролью, статусом
и действиями с промежутками 12px; на узком экране строка переносится.
Счётчики фильтров используют кеш первой страницы и помечают нижнюю границу
как `20+`. Доска показывает число загруженных задач и `+`, если есть ещё.
API пока не возвращает totals, username, аватары, тип источника и модель
названия доски. До готовности этих контрактов не имитируем редактирование
названия: показываем «BotFlow», источник «Telegram» и имена без вымышленных
ников. План последующего подключения описан в дизайн-промпте и комментарии #12.

## Дополнение: полный сценарий Drag & Drop (#18)

Ветка #18 включает коммит #12 как зависимость. Нового backend API и поля
позиции нет. PointerSensor определяет цель по положению указателя, поэтому
длинная карточка не превращает сброс за пределами колонок в допустимый drop.
Перенос стрелками исключён по решению пользователя после повторной проблемы
в сквозной проверке. Escape отменяет перенос мышью/touch. Клавиатурный путь
сохраняется через Enter на карточке, обычный select статуса и кнопку сохранения
в модальном окне. Ручка исключена из последовательности Tab.

PATCH использует снимок задачи в начале drag, а не незаметно обновлённую
версию из фонового чтения. Ответ mutation и GET после ошибки не заменяет
более свежую версию, уже известную кешу. После 403, как и после 409 или
потерянного ответа, перечитываются карточка и доска без повторения PATCH.
Сессия и права перепроверяются; сервер остаётся окончательной проверкой.

`frontend/e2e/dnd.spec.ts` включён в общий `make e2e`: настоящий Tasks API,
пустая колонка, один PATCH с ожидаемой версией, мышь/touch и клавиатура через окно,
отмена и недопустимый drop, отсутствие ручек у чужих задач обычного участника,
реальный серверный 403, настоящий конкурентный 409 и потеря ответа после
успешного commit. Тестовая fixture `dnd-board` создаёт только два задания
в одноразовом Compose-проекте; публичных тестовых endpoints нет.
`dnd-ui.spec.ts` отдельно проверяет RU/HY, перечитывание после 403 и гонки
фонового чтения с начатым drag и поздним ответом mutation.
