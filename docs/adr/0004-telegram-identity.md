# Telegram как идентичность участника

Telegram связывает бота и веб-панель с одной учётной записью. Для входа пользователь получает в боте одноразовый случайный код на 32 URL-safe символа, действующий 5 минут. Новый код отменяет предыдущий; обмен атомарный, в БД хранится хеш. Email/password и отдельная привязка аккаунтов не вводятся.

Доступ к команде требует заявки и одобрения admin. После отклонения можно подать новую заявку; блокировку нельзя обойти новой заявкой. Разблокировка восстанавливает допуск, но требует нового входа. Первый admin создаётся отдельной идемпотентной командой по INITIAL_ADMIN_TELEGRAM_ID; повтор не сбрасывает решения о доступе.

Допуск проверяется через Identity на каждом новом защищённом запросе и при приёме сообщения. При недоступном Identity новая операция не принимается. Правомерно принятое до блокировки задание завершается с исходным автором; блокировка не даёт ему нового доступа и подавляет итоговое уведомление о задаче.
