# Сохранённый workflow без Saga-координатора

Обработка сообщения использует сохранённые стадии, outbox/inbox, идемпотентность, ограниченные повторы и операторский replay. Отдельный Saga-координатор не вводится, поскольку между шагами нет согласованного бизнес-действия для компенсации.

Ошибка распознавания не создаёт задачу; недоступный Tasks оставляет результат для доставки; ошибка уведомления не откатывает задачу. Команды/результаты идут через RabbitMQ, локальные STT/уведомления — через Redis Streams. Появление сценария с компенсациями потребует пересмотра решения.
