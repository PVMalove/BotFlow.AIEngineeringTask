# Аутентификация внутренних HTTP-вызовов

Внутренние HTTP-вызовы используют отдельные случайные сервисные ключи по вызывающему сервису и ограниченные разрешённые операции. Это позволяет Automation подтверждать Telegram-идентичность до появления пользовательского JWT.

Ключ подключается как секрет, не попадает во frontend/логи; внутренние endpoints не публикуются через веб-вход. Сервисный ключ не даёт общих admin-полномочий и не заменяет проверку пользователя/допуска. Ротация ручная; отдельные service JWT/mTLS не вводятся для локального профиля.
