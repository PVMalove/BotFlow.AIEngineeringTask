# Операторское восстановление очередей

> Границы первой версии уточнены в [ADR-0021](0021-proportionate-reliability.md):
> расширенные процедуры восстановления и очистки не входят в обязательную поставку.

При полной потере Redis Streams обработка восстанавливается операторским replay из сохранённых состояний/исходных данных PostgreSQL. Команда сохраняет исходные ID, не создаёт вторую задачу; зависшие операции видны оператору. Фоновая автоматическая сверка потерянных сообщений не вводится.

Межсервисные сообщения находятся в RabbitMQ, поэтому потеря Redis не означает их потерю. Pub/Sub восстанавливается перечитыванием REST, временный FSM-контекст можно сбросить. Полная потеря RabbitMQ требует отдельной сверки и безопасного replay, обычные рестарты/временные отказы обоих брокеров восстанавливаются автоматически.

Replay зависит от сохранности PG и нужных объектов MinIO. Публикация в брокер не является доказательством завершения workflow. Процедуры полной потери очереди проверяются в изолированной среде.
