# Три независимых сервиса

BotFlow разделён на Identity, Tasks и Automation. Identity владеет пользователями, допуском и входом; Tasks — задачами, статусами и доской; Automation — Telegram и обработкой сообщений. Это позволяет независимо развивать бизнес-модель задач и интеграционный workflow. Модульный монолит потребовал бы меньше инфраструктуры, но сильнее связал бы их жизненные циклы.

У каждого сервиса собственный PostgreSQL-контейнер, модель и миграции. Его API и workers используют только его БД; межсервисные ссылки передаются как ID, внешние ключи применяются внутри своей БД. Worker — процесс внутри сервиса, а не самостоятельный доменный контекст. Цена разделения — межсервисные контракты, частичные отказы и интеграционные проверки.
